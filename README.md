## Описание проекта


MYWIKI – это легковесное веб-приложение для организации личной или командной базы знаний на основе Markdown-файлов.  

Оно позволяет:


- Хранить страницы в PostgreSQL с полнотекстовым поиском (на русском языке).

- Импортировать `.md` файлы из папки `pages/` – как целиком, так и инкрементально (только новые/изменённые).

- Просматривать страницы с рендерингом Markdown (через Parsedown).

- Искать по номеру, языку, теме и содержимому с ранжированием релевантности.

- Автоматически обновлять код и базу данных при push в репозиторий (через вебхук).

- Копировать блоки кода одной кнопкой.

- Работать через Docker (контейнеры с PHP и PostgreSQL).


Проект предназначен для быстрого развёртывания на сервере (например, VPS) и удобного пополнения знаний через Git.


---


## Технологии


- **Backend:** PHP 8.x (с модулем PDO_PGSQL)

- **База данных:** PostgreSQL 15 с полнотекстовым поиском (`tsvector`)

- **Контейнеризация:** Docker + Docker Compose

- **Сборка:** собственный `Dockerfile` на основе официального PHP-образа с Apache

- **Фронтенд:** чистый HTML/CSS/JS (без фреймворков)

- **Markdown-парсер:** Parsedown (встроенный)

- **Вебхук:** автоматический `git pull` и запуск импорта

## Установка и запуск


### 1. Клонирование репозитория

```bash

git clone git@github.com:testbybyscan-del/MYWIKI.git

cd MYWIKI

```


### 2. Создание файла `.env`

Скопируйте пример и отредактируйте под свои нужды:

```bash

cp .env.example .env

```

Пример содержимого `.env`:

```

POSTGRES_DB=wiki

POSTGRES_USER=wiki_user

POSTGRES_PASSWORD=secure_password_change_me

WIKI_PORT=53002

DB_HOST=db

DB_NAME=wiki

DB_USER=wiki_user

DB_PASSWORD=secure_password_change_me

```

Обратите внимание: `DB_HOST` должен указывать на имя сервиса `db` (как в docker-compose.yml).


### 3. Запуск контейнеров

```bash

docker-compose up -d

```

После первого запуска база данных инициализируется скриптом `init-db.sql` (создаётся таблица `pages` с поисковым вектором).


Приложение будет доступно по адресу: `http://ваш_сервер:53002` (порт настраивается через `WIKI_PORT`).

## Импорт данных (страницы)


Все страницы должны быть Markdown-файлами (расширение `.md`) и лежать в папке `pages/` (создаётся автоматически, но может быть пустой).  

Файлы должны именоваться по шаблону:


```

[номер]._[язык]._[тема].md

```


**Примеры:**

- `0001._php._array.md`

- `0002._js._closures.md`

- `0003._python._decorators.md`


Где:

- `номер` – порядковый номер (можно с ведущими нулями, сортировка числовая)

- `язык` – язык программирования или тег

- `тема` – краткое название темы


**Первая строка файла** считается заголовком страницы (если начинается с `#`, то хеш удаляется).


### Запуск импорта

```bash

docker exec -it wiki-pesah php import.php

```

Флаги:

- `--force` – пересоздать таблицу (удалить все старые записи)

- `--incremental` – добавить только новые файлы и обновить существующие (по имени файла)


**Рекомендуется** использовать инкрементальный режим после каждого обновления репозитория.

## Структура базы данных


Таблица `pages`:

```sql

CREATE TABLE pages (

    id SERIAL PRIMARY KEY,

    filename TEXT UNIQUE NOT NULL,

    title TEXT NOT NULL,

    num TEXT,

    lang TEXT,

    topic TEXT,

    content TEXT NOT NULL,

    search_vector TSVECTOR GENERATED ALWAYS AS (

        setweight(to_tsvector('russian', coalesce(num, '')), 'A') ||

        setweight(to_tsvector('russian', coalesce(lang, '')), 'B') ||

        setweight(to_tsvector('russian', coalesce(topic, '')), 'B') ||

        setweight(to_tsvector('russian', coalesce(title, '')), 'A') ||

        setweight(to_tsvector('russian', coalesce(content, '')), 'C')

    ) STORED

);

```

- Поле `search_vector` автоматически обновляется при вставке/обновлении.

- Используются индексы GIN для быстрого полнотекстового поиска.

## Веб-интерфейс и поиск


- **Оглавление** – список всех страниц из БД, сортировка по номеру.

- **Поиск** – работает через AJAX (без перезагрузки страницы). Запрос отправляется в `index.php?ajax=search&q=...`.

- **Выдача** – показывает релевантность в процентах, подсвечивает совпадения в тексте страницы.

- **Просмотр** – при клике на страницу или результат поиска содержимое подгружается через `load_file.php?file=...` и рендерится в Markdown.

- **Копирование кода** – у каждого блока `<pre><code>` появляется кнопка "Копировать".

## Автоматическое обновление (вебхук)


Скрипт `webhook.php` предназначен для приёма POST-запросов от GitHub при каждом push в ветку `main`. Он выполняет:


1. Проверку подписи (секретный токен).

2. `git pull origin main` – обновляет код.

3. `php import.php --incremental` – импортирует новые или изменённые файлы.


### Настройка вебхука на GitHub

1. Перейдите в настройки вашего репозитория → Webhooks → Add webhook.

2. **Payload URL:** `https://ваш_домен/webhook.php`

3. **Content type:** `application/json`

4. **Secret:** установите такой же, как в `webhook.php` (замените `'your_secret_token'`).

5. Выберите события: **Just the push event**.

6. Сохраните.


После этого каждый push будет автоматически обновлять сайт и базу данных.

## Структура проекта


```

MYWIKI/

├── docker-compose.yml     # Оркестрация контейнеров (db + wiki)

├── Dockerfile             # Сборка PHP-образа с Apache и необходимыми модулями

├── .dockerignore          # Исключения для сборки образа

├── .env.example           # Пример переменных окружения (копируйте в .env)

├── .gitignore             # Игнорируемые файлы (pg_data/, pages/*, .env и др.)

├── pages/                 # Директория с .md файлами (содержимое игнорируется Git, кроме .gitkeep)

│   └── .gitkeep           # Заглушка для сохранения папки в репозитории

├── init-db.sql            # SQL-скрипт инициализации таблицы pages

├── import.php             # Консольный скрипт импорта .md файлов в БД

├── index.php              # Главная страница (список, поиск, отрисовка)

├── load_file.php          # Загрузка и рендеринг одной страницы по имени файла

├── webhook.php            # Обработчик вебхука GitHub

├── Parsedown.php          # Библиотека для парсинга Markdown (версия 1.7.4)

├── script.js              # Клиентская логика (поиск, навигация, копирование)

├── styles.css             # Стили (адаптивный дизайн)

├── structure              # (служебный файл, можно игнорировать)

└── pg_data/               # Том PostgreSQL (создаётся автоматически, не в Git)

```

## Переменные окружения (`.env`)


| Переменная          | Описание                                  | Значение по умолчанию (в коде) |

|---------------------|-------------------------------------------|--------------------------------|

| `POSTGRES_DB`       | Имя базы данных                           | `wiki`                         |

| `POSTGRES_USER`     | Пользователь БД                           | `wiki_user`                    |

| `POSTGRES_PASSWORD` | Пароль пользователя                       | `secure_password_change_me`    |

| `WIKI_PORT`         | Порт для доступа к веб-интерфейсу         | `53002`                        |

| `DB_HOST`           | Хост БД (имя сервиса в docker-compose)   | `db`                           |

| `DB_NAME`           | Имя БД (дублируется)                      | `wiki`                         |

| `DB_USER`           | Пользователь БД (дублируется)             | `wiki_user`                    |

| `DB_PASSWORD`       | Пароль (дублируется)                      | `secure_password_change_me`    |


> **Важно:** Замените пароли на надёжные перед развёртыванием на продакшене.

## Работа с данными изнутри контейнера


- **Запуск импорта вручную:**

  ```bash

  docker exec -it wiki-pesah php import.php --incremental

  ```

- **Проверка логов:**  

  Логи пишутся в `/tmp/wiki_debug.log` внутри контейнера. Можно посмотреть:

  ```bash

  docker exec wiki-pesah cat /tmp/wiki_debug.log

  ```
